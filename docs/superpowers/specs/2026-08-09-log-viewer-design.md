# 日志查看入口设计

## 目标

让不熟悉命令行的 Windows 用户能够在项目根目录双击一个文件查看签到日志，同时为需要观察运行过程的用户提供 PowerShell 实时查看命令。

## 方案

仓库根目录新增 `查看日志.bat`。脚本使用自身所在目录定位 `logs\checkin.log`，因此无论用户把项目解压到哪里、从哪个当前目录启动，都能找到正确日志。

- 日志存在：调用 Windows 记事本打开日志，并以退出码 `0` 结束。
- 日志不存在：在控制台显示“尚未生成日志，请先运行一次签到程序。”，等待用户按键后以非零退出码结束。
- 路径包含中文或空格：所有路径均使用双引号。

README 的“如何判断是否成功”章节增加三种入口：双击 `查看日志.bat`、直接打开 `logs\checkin.log`、使用 `Get-Content .\logs\checkin.log -Wait` 实时跟踪。

## 测试

新增 Python 测试，在临时目录复制并运行批处理脚本。为避免测试真正打开记事本，测试目录提供同名的临时 `notepad.cmd`，记录收到的日志路径；测试分别验证：

1. 日志存在时脚本退出码为 `0`，且传递给记事本的是脚本目录下的 `logs\checkin.log`。
2. 日志不存在时脚本退出码非零，并输出明确的中文提示。

## 边界与安全

脚本只读取日志，不修改、上传或删除任何文件。日志仍由 `.gitignore` 排除，不会提交到公开仓库。脚本不显示账号密码，也不读取 App 数据；用户分享日志前仍需自行检查昵称、设备序列号和路径等信息。
