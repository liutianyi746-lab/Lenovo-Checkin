# 漏跑签到自动恢复设计

## 目标

保留每天 00:01 的联想签到主任务。当电脑在 00:01 关机、休眠或任务没有执行时，在用户当天登录 Windows 后自动检查并补跑；若当天已经成功签到，则不启动雷电模拟器，也不重复签到。

## 任务结构

- `联想每日自动签到`：继续每天 00:01 运行，并启用“错过计划时间后尽快运行”。
- `联想签到漏跑检查`：在当前用户登录 Windows 时运行轻量检查程序。
- 两个任务都使用项目虚拟环境中的 Python，工作目录固定为项目根目录，不依赖 Codex。

## 检查规则

检查程序读取 `logs/checkin.log`，只认可当天日期对应的以下成功记录：

- `[SUCCESS] 签到成功`
- `[SUCCESS] 今日已经签到，无需重复操作`

如果当天存在其中任意一条，检查程序以退出码 0 结束，不启动模拟器。如果不存在，则调用同一 Python 解释器运行 `main.py`，并原样返回 `main.py` 的退出码。

## 并发与幂等

登录检查和 00:01 主任务可能在时间上重叠。`main.py` 已有运行锁和签到页面幂等判断，因此补跑程序不自行点击页面，也不绕过主程序。任务计划程序同时设置为“已有实例运行时不启动新实例”。

## 失败处理

- 日志不存在、日志无法读取或当天没有成功记录，都视为需要补跑。
- 补跑失败时保留主程序生成的日志、截图和 hierarchy XML。
- 验证码、滑块、短信验证、设备验证、账号安全验证或风控页面仍由主程序安全停止，不尝试绕过。
- 主程序结束后继续按现有逻辑关闭雷电模拟器。

## 可移植安装

项目新增 Python 检查入口和 Windows 任务安装脚本。安装脚本根据自身所在目录解析项目路径与虚拟环境，不写死其他用户的用户名、Python 路径或雷电安装路径；雷电路径继续由现有配置自动发现或配置文件提供。

## 验证

- 单元测试覆盖：当天已成功时不运行 `main.py`；当天无成功、日志不存在、仅有昨日成功时运行 `main.py`；补跑退出码透传。
- 安装后读取两个 Windows 计划任务，确认 00:01、登录触发器、“错过后尽快运行”和禁止并发设置。
- 手动运行漏跑检查任务，确认今天已有成功日志时不会启动雷电。
